# BFD-EPIC-001 Implementation Plan

**Goal:** Build a pixel-faithful, statically-rendered food-ordering home page that reproduces Figma frame `88:72` (`food-order-home`, 390 × 1461) exactly, verified by geometry and computed-style assertions in a real browser.

**Architecture:** This is a **greenfield repository** — `git ls-files` returns only `readme` (empty), `.env`, `.arc-base-commit` and four design artifacts. There is no `CLAUDE.md`, no `docs/decisions/`, no `package.json`, and none of the components the design review's `component_map` calls "existing" actually exist here (that catalogue belongs to the arc platform repo, not this one). So the plan establishes the conventions: a Vite + React + TypeScript SPA; the frame's palette shipped as a `[data-theme="food-order-light"]` token scope whose slots Tailwind v4 binds via `@theme inline`; one component file per Figma node group, composed by `HomePage`. Tests are split by what they can honestly prove — **Vitest/jsdom owns content and semantics** (jsdom computes no layout, so it cannot verify AC-1), **Playwright/Chromium at viewport 390 × 1461 owns geometry and colour**, which is the only real test of "looks like the given figma design".

**Tech Stack:** Vite 6 · React 19 · TypeScript (strict) · Tailwind CSS v4 (`@tailwindcss/vite`) · `lucide-react` · `@fontsource-variable/outfit` + `@fontsource-variable/figtree` (self-hosted so CI needs no network) · Vitest + `@testing-library/react` + jsdom · Playwright (Chromium) · `sharp` (dev-only, asset extraction).

## Verified frame facts

Every number below was read out of `docs/superpowers/designs/figma-frame.json`. The frame is a `SECTION` at absolute `(1618, −172)` with **no auto-layout**, so its children are absolutely placed and two of them overlap. Frame-relative coordinates (`x − 1618`, `y + 172`):

| Node | id | rel x, y | w × h |
| --- | --- | --- | --- |
| status-bar | 89:182 | 0, 0 | 390 × 44 |
| header | 89:188 | 0, 44 | 390 × 68 |
| search-section | 89:198 | 0, 112 | 390 × 68 |
| categories-carousel | 89:205 | 0, 180 | 390 × 62 |
| promo-banner | 89:230 | 20, 225 | 350 × 130 |
| spacer *(dropped)* | 89:238 | 0, 242 | 390 × 145 |
| restaurant-feed-section | 89:239 | 0, 387 | 390 × 1034 |

The carousel's box is 62 tall (38px pills + `paddingBottom: 24`) and ends at y 242, but the banner starts at y 225 — a 17px overlap. `spacer` (89:238) spans y 242–387 and also overlaps the banner. Neither is a real gap; they are canvas artifacts of an absolutely-positioned section. **The equivalent flow layout, which reproduces every child's position exactly, is:**

```
44 (status bar) + 68 (header) + 68 (search section) = 180
180 + 38 (pill row) = 218   → 7px gap → 225 (banner top)
225 + 130 = 355             → 32px gap → 387 (feed top)
387 + 1034 (feed) = 1421    → 40px bottom padding → 1461 ✓
```

So the carousel's `paddingBottom` is implemented as **7px**, not 24px, and `spacer` is not translated to markup.

## Deliberate omissions (outside AC-1)

No routing, data fetching, interaction state, responsive breakpoints, hover/pressed/focus/disabled/loading/empty states, bottom navigation, or line-clamping. None appears in the frame, and AC-1 asks only that the loaded page match it. Controls are rendered as real, focusable, labelled elements with no handlers.

**Stated assumptions** (from the design review's open questions, resolved so work is not blocked):
1. **Images.** The 8 `imageRef`s are not exported and there is no Figma token in `.env`. Task 2 recovers them deterministically from `figma-frame.png` (which is exactly 2× the frame): 7 regions are pure photography and crop losslessly; the promo photo is recovered by algebraically un-compositing the known scrim, then diffusing over the three baked-in text boxes — which the DOM overlay covers anyway.
2. **DOM order.** The Figma child order inside `card-body` puts the restaurant name third. The DOM leads with the name (`<h3>`) and CSS `order` restores the visual order, as the review recommended.
3. **The `spacer` node is a canvas artifact** and is dropped — see the flow-layout derivation above.
4. **Unsaved heart** ships exactly as drawn (grey solid `#4B5563`), because AC-1 is fidelity to the frame; the review's outline-heart suggestion is a design change, not an implementation one.
5. **Dev/preview port is 3001**, from `ARC_WEB_PORT` in `.env`.

```ts
import { expect, type Locator } from '@playwright/test'

export interface Box {
  x: number
  y: number
  w: number
  h: number
}

/** Asserts a node's viewport-relative box. The viewport is the frame, so these are frame coordinates. */
export async function expectBox(locator: Locator, expected: Box, tol = 1): Promise<void> {
  const box = await locator.boundingBox()
  expect(box, `expected ${await locator.count()} visible node(s) with a layout box`).not.toBeNull()
  const actual = { x: box!.x, y: box!.y, w: box!.width, h: box!.height }
  for (const key of ['x', 'y', 'w', 'h'] as const) {
    expect(
      Math.abs(actual[key] - expected[key]),
      `${key}: expected ${expected[key]}, got ${actual[key]}`,
    ).toBeLessThanOrEqual(tol)
  }
}

/** Asserts resolved CSS property values. */
export async function expectStyles(
  locator: Locator,
  expected: Record<string, string>,
): Promise<void> {
  const actual = await locator.evaluate(
    (el, props: string[]) =>
      Object.fromEntries(
        props.map((p) => [p, getComputedStyle(el as Element).getPropertyValue(p).trim()]),
      ),
    Object.keys(expected),
  )
  expect(actual).toEqual(expected)
}
```

```js
// Recovers the frame's eight photographs from the 2x render of Figma node 88:72.
// Run with: npm run assets
import { mkdir } from 'node:fs/promises'
import { fileURLToPath } from 'node:url'
import sharp from 'sharp'

const SCALE = 2
const SRC = fileURLToPath(new URL('../docs/superpowers/designs/figma-frame.png', import.meta.url))
const OUT = fileURLToPath(new URL('../src/assets/', import.meta.url))

/** Frame-coordinate boxes that contain photography only. */
const CLEAN = [
  { file: 'avatar.jpg', x: 330, y: 56, w: 40, h: 40 },
  { file: 'bella-1.jpg', x: 20, y: 432, w: 115.5, h: 120 },
  { file: 'bella-2.jpg', x: 137.5, y: 432, w: 115, h: 120 },
  { file: 'bella-3.jpg', x: 254.5, y: 432, w: 115.5, h: 120 },
  { file: 'sakura-1.jpg', x: 20, y: 947, w: 115.5, h: 120 },
  { file: 'sakura-2.jpg', x: 137.5, y: 947, w: 115, h: 120 },
  { file: 'sakura-3.jpg', x: 254.5, y: 947, w: 115.5, h: 120 },
]

/** promo-banner 89:230 and, banner-relative, the three text boxes baked over it. */
const PROMO = { x: 20, y: 225, w: 350, h: 130 }
const TEXT_BOXES = [
  { x: 20, y: 22.5, w: 118, h: 21 }, // badge 89:232
  { x: 20, y: 51.5, w: 200, h: 56 }, // headline 89:234
  { x: 267, y: 20, w: 63, h: 54 }, // 50% / OFF NOW 89:235
]
const PAD = 3

/** The scrim from node 89:230, sampled at horizontal position t in [0, 1]. */
function scrimAt(t) {
  if (t <= 0.6) {
    const u = t / 0.6
    return { c: [17, 24, 39], a: 0.902 + (0.667 - 0.902) * u }
  }
  const u = (t - 0.6) / 0.4
  return {
    c: [17 + (226 - 17) * u, 24 + (114 - 24) * u, 39 + (91 - 39) * u],
    a: 0.667 + (0.4 - 0.667) * u,
  }
}

const px = (v) => Math.round(v * SCALE)
const clamp = (v) => (v < 0 ? 0 : v > 255 ? 255 : v)

async function main() {
  await mkdir(OUT, { recursive: true })

  for (const { file, x, y, w, h } of CLEAN) {
    await sharp(SRC)
      .extract({ left: px(x), top: px(y), width: px(w), height: px(h) })
      .jpeg({ quality: 92, chromaSubsampling: '4:4:4' })
      .toFile(OUT + file)
    console.log(`${file}  ${px(w)}x${px(h)}`)
  }

  const W = px(PROMO.w)
  const H = px(PROMO.h)
  const { data } = await sharp(SRC)
    .extract({ left: px(PROMO.x), top: px(PROMO.y), width: W, height: H })
    .removeAlpha()
    .raw()
    .toBuffer({ resolveWithObject: true })

  // 1. Undo the scrim: photo = (composited - colour * alpha) / (1 - alpha).
  const rgb = new Float32Array(W * H * 3)
  for (let x = 0; x < W; x++) {
    const { c, a } = scrimAt(x / (W - 1))
    const inv = 1 - a
    for (let y = 0; y < H; y++) {
      const i = (y * W + x) * 3
      for (let k = 0; k < 3; k++) rgb[i + k] = clamp((data[i + k] - c[k] * a) / inv)
    }
  }

  // 2. Mask the baked-in text.
  const masked = new Uint8Array(W * H)
  for (const box of TEXT_BOXES) {
    const x0 = Math.max(0, px(box.x) - PAD)
    const y0 = Math.max(0, px(box.y) - PAD)
    const x1 = Math.min(W, px(box.x + box.w) + PAD)
    const y1 = Math.min(H, px(box.y + box.h) + PAD)
    for (let y = y0; y < y1; y++) for (let x = x0; x < x1; x++) masked[y * W + x] = 1
  }

  // 3. Seed each masked run by interpolating between its horizontal neighbours.
  for (let y = 0; y < H; y++) {
    let x = 0
    while (x < W) {
      if (!masked[y * W + x]) {
        x++
        continue
      }
      let end = x
      while (end < W && masked[y * W + end]) end++
      const left = x - 1
      const right = end
      for (let k = 0; k < 3; k++) {
        const a = left >= 0 ? rgb[(y * W + left) * 3 + k] : rgb[(y * W + right % W) * 3 + k]
        const b = right < W ? rgb[(y * W + right) * 3 + k] : a
        for (let i = x; i < end; i++) {
          const t = (i - x + 1) / (end - x + 1)
          rgb[(y * W + i) * 3 + k] = a + (b - a) * t
        }
      }
      x = end
    }
  }

  // 4. Relax the seeded pixels toward the discrete Laplace solution so the seams vanish.
  const next = Float32Array.from(rgb)
  for (let pass = 0; pass < 80; pass++) {
    for (let y = 1; y < H - 1; y++) {
      for (let x = 1; x < W - 1; x++) {
        if (!masked[y * W + x]) continue
        const i = (y * W + x) * 3
        for (let k = 0; k < 3; k++) {
          next[i + k] =
            (rgb[i - 3 + k] + rgb[i + 3 + k] + rgb[i - W * 3 + k] + rgb[i + W * 3 + k]) / 4
        }
      }
    }
    rgb.set(next)
  }

  const out = Buffer.alloc(W * H * 3)
  for (let i = 0; i < out.length; i++) out[i] = clamp(Math.round(rgb[i]))
  await sharp(out, { raw: { width: W, height: H, channels: 3 } })
    .jpeg({ quality: 92, chromaSubsampling: '4:4:4' })
    .toFile(OUT + 'promo-pizza.jpg')
  console.log(`promo-pizza.jpg  ${W}x${H}`)
}

await main()
```

```tsx
import type { ComponentPropsWithoutRef, ReactNode } from 'react'
import type { LucideIcon } from 'lucide-react'

const SIZE = {
  /** Figma 89:206 — category pill. */
  md: 'h-[38px] gap-2 px-4 text-[14px]/[16.8px] font-semibold',
  /** Figma 89:251 — card tag. */
  sm: 'h-[26px] px-2.5 text-[12px]/[14.4px] font-medium',
} as const

const TONE = {
  brand: 'bg-brand text-on-brand',
  muted: 'border border-border bg-surface-2',
} as const

interface PillOwnProps {
  size: keyof typeof SIZE
  tone: keyof typeof TONE
  icon?: LucideIcon
  children: ReactNode
  /** data-node stamped on the label span, so fidelity tests can target the text node itself. */
  labelNode?: string
  labelClassName?: string
  className?: string
}

type PillProps =
  | (PillOwnProps & { as: 'button' } & Omit<ComponentPropsWithoutRef<'button'>, keyof PillOwnProps>)
  | (PillOwnProps & { as?: never } & Omit<ComponentPropsWithoutRef<'span'>, keyof PillOwnProps>)

export function Pill(props: PillProps) {
  const { size, tone, icon: Icon, children, labelNode, labelClassName, className, ...rest } = props
  const { as, ...attrs } = rest as { as?: 'button' } & Record<string, unknown>

  const shell = [
    // Figma cornerRadius is literally 100, not a pill-infinite radius.
    'inline-flex shrink-0 items-center justify-center rounded-[100px] whitespace-nowrap',
    SIZE[size],
    TONE[tone],
    className ?? '',
  ].join(' ')

  const content = (
    <>
      {Icon ? <Icon size={18} strokeWidth={2} /> : null}
      <span data-node={labelNode} className={labelClassName}>
        {children}
      </span>
    </>
  )

  return as === 'button' ? (
    <button type="button" {...attrs} className={shell}>
      {content}
    </button>
  ) : (
    <span {...attrs} className={shell}>
      {content}
    </span>
  )
}
```

## Verification notes for the implementing agent

- **Run Playwright, not just Vitest.** jsdom applies no CSS and computes no layout; a green Vitest run says nothing about AC-1.
- **Fonts must be loaded before any box assertion.** Text widths (`90`, `123`, `162`, `258`…) and the description's 4-line / 3-line wrap are Figtree and Outfit metrics. If a box test fails by a few pixels, check the font loaded before adjusting the expectation.
- **Tolerances are deliberate:** 1px for frames and containers, 2px for text nodes and hug-sized pills whose width is a glyph-advance sum.
- **Three computed-style strings are serialization-sensitive** and may need adjusting to what Chromium actually prints once run: the two `box-shadow` values and `rgba(255, 255, 255, 0.667)`. Adjust the expected string to the observed one only after confirming the *input* CSS matches the frame values quoted in the "Verified frame facts" table.
